# 0001. 기술 스택과 구조 — Vite + React 19 + TypeScript + FSD

- 상태: 채택
- 날짜: 2026-08-19

## 배경

night lexicon(음악 사전 포트폴리오)은 신규 프로젝트다. HTML 프로토타입으로
디자인 방향을 검증했고, 실제 서비스로 전환할 스택과 구조가 필요했다.

## 결정

- 번들러/개발서버: Vite 7
- UI: React 19 + TypeScript (strict)
- 구조: Feature-Sliced Design (app → pages → widgets → features → entities → shared)
- 테스트: Vitest + Testing Library (jsdom)
- 린트: ESLint 9 flat config + typescript-eslint + react-hooks
- 검증 센서: ~/.config/opencode/scripts/verify.sh (typecheck/lint/test/build)

## 이유와 대안

- 벽 패닝·전환 연출은 DOM transform만으로 충분해 캔버스/웹GL을 배제했다.
  정적 HTML 프로토타입에서 이미 DOM 방식으로 충분히 매끄러운 것을 확인했다.
- 상태가 얕다(필터/선택/호버). 상태 관리 라이브러리(Zustand 등)는 지금은 과하다고
  판단해 React state로 시작하고, 필요 시 features/model로 분리해 도입한다.
- 데이터는 소규모라 코드 내 `TRACKS` 배열로 시작한다. 콘텐츠가 늘면 JSON/MDX
  분리 또는 CMS를 검토한다.
- 대안으로 Next.js(SSR)를 검토했으나, 단일 페이지 인터랙션 중심이고 SEO 요구가
  작아 SPA가 더 가볍다고 판단했다.

## 영향

- 모든 커밋은 verify.sh 통과 상태여야 한다.
- 레이어 간 import 규칙(위→아래 단방향, public index만 사용)을 리뷰에서 강제한다.
- 콘텐츠 추가는 entities/track/model/data.ts 수정으로 한정된다.
